# แก้ปัญหาที่พบบ่อย

## คำสั่ง Docker ที่ต้องจำ

| ต้องการ | คำสั่ง |
|---|---|
| เปิดทุกอย่าง | `docker compose up -d` |
| ดูสถานะ | `docker compose ps` |
| ดู log (กด Ctrl+C ออก) | `docker compose logs -f backend` หรือ `frontend` |
| รีสตาร์ตตัวเดียว | `docker compose restart backend` |
| ปิดทั้งหมด (ข้อมูลยังอยู่) | `docker compose down` |
| ล้างฐานข้อมูลเริ่มใหม่หมด ⚠️ | `docker compose down -v` แล้ว `docker compose up -d` |
| เข้าไปพิมพ์คำสั่งใน container | `docker compose exec backend sh` |
| เข้า MySQL ด้วยคำสั่ง | `docker compose exec db mysql -uroot -proot1234 bpes` |

## อาการ → สาเหตุ → วิธีแก้

| อาการ | สาเหตุ | แก้ |
|---|---|---|
| หน้าเว็บกล่องแดง "เชื่อมต่อ API ไม่ได้" | backend ล่ม | `docker compose logs backend` ดูบรรทัดสุดท้าย |
| log backend `Cannot find module './routes/xxx'` | ลบ `//` ใน `server.js` ก่อนสร้างไฟล์ หรือพิมพ์ชื่อไฟล์ผิด | ใส่ `//` กลับ หรือแก้ชื่อไฟล์ |
| log backend `SyntaxError ... server.js:12` | พิมพ์โค้ดผิดที่บรรทัดนั้น | เปิดไฟล์ไปบรรทัดที่บอก ตรวจวงเล็บ `( ) { }` และ `,` |
| log backend `ER_NO_SUCH_TABLE` | ตารางยังไม่ถูกสร้าง | `docker compose restart backend` (seed สร้างให้) |
| log backend `ER_BAD_FIELD_ERROR` | ชื่อคอลัมน์ใน SQL ไม่ตรง `schema.sql` | แก้ชื่อให้ตรง ถ้าแก้ `schema.sql` เพิ่มคอลัมน์ ต้อง `docker compose down -v` |
| หน้าเว็บขาว | error ใน `.vue` | F12 → Console ดูชื่อไฟล์และบรรทัด |
| `[plugin:vite:vue] ... Element is missing end tag` | แท็กใน `<template>` ปิดไม่ครบ | นับ `<div>` กับ `</div>` ให้เท่ากัน |
| `Failed to resolve import "./pages/XxxPage.vue"` | ยังไม่สร้างไฟล์ หรือชื่อตัวพิมพ์เล็กใหญ่ไม่ตรง | ชื่อไฟล์ต้องตรงทุกตัวอักษร หรือกลับไปใช้ `NotReady.vue` |
| แก้ไฟล์แล้วไม่เปลี่ยน | Windows ไม่ส่งสัญญาณไฟล์เปลี่ยนเข้า Docker | ตรวจ `usePolling: true` และ `nodemon -L` แล้ว restart |
| 401 ทุกครั้งทั้งที่ login แล้ว | token หมดอายุ หรือเปลี่ยนรหัสแล้ว | ออกจากระบบแล้ว login ใหม่ |
| 403 "กรุณาเปลี่ยนรหัสผ่านครั้งแรก" | บัญชียังไม่เปลี่ยนรหัส | เปลี่ยนรหัสผ่านก่อน (ถูกต้องตามออกแบบ) |
| 403 "รอบยังไม่เปิด หรืออยู่นอกวันประเมิน" | รอบยังเป็น draft หรือวันเริ่มเป็นวันหลัง | admin เปิดรอบ / สร้างรอบที่เริ่มวันนี้ |
| ลืมรหัส admin ที่เปลี่ยนแล้ว | — | `docker compose down -v` แล้ว up ใหม่ (ข้อมูลหายหมด) |
| `port is already allocated` | โปรแกรมอื่นใช้พอร์ต | เปลี่ยนเลขซ้ายใน `ports` ของ compose |
| `npm install` ใน container ค้างนาน / `ETIMEDOUT` | ไม่มีอินเทอร์เน็ต | ดูแผนสำรองด้านล่าง |

## แผนสำรอง: ไม่มีอินเทอร์เน็ตให้ `npm install` ใน Docker

ถามกรรมการวันแรกว่าเครื่องแข่งออกอินเทอร์เน็ตไปที่ npm ได้ไหม และ Docker image ที่เตรียมมีอะไรบ้าง

- ถ้ากรรมการมี image `node` และ `mysql` ให้แล้ว แต่ไม่มีเน็ต → ให้ติดตั้งไลบรารีจากเครื่องที่มีเน็ตในวันตรวจเครื่อง (`docker compose up` ครั้งแรกในวันแรก) volume ของ `node_modules` จะเก็บไว้ให้ ห้ามใช้ `docker compose down -v` หลังจากนั้น
- ถ้า Docker ใช้ได้แค่ MySQL → รัน MySQL ใน Docker แต่รัน backend/frontend ด้วย Node บนเครื่อง (ต้องเป็น Node 20.19 ขึ้นไป เพราะ Vite 7):

```powershell
# Terminal 1 — เปิดเฉพาะฐานข้อมูล
docker compose up -d db phpmyadmin

# Terminal 2 — backend บนเครื่อง
cd C:\bpes\backend
$env:DB_HOST="127.0.0.1"; $env:DB_PORT="3307"; $env:DB_PASSWORD="root1234"; $env:DB_NAME="bpes"
$env:JWT_SECRET="bpes-2568-change-this-to-a-long-random-secret-key"
npm install
npm run seed
npm run dev

# Terminal 3 — frontend บนเครื่อง
cd C:\bpes\frontend
npm install
npm run dev
```

เปิด http://localhost:5175 ได้เหมือนเดิม (vite ส่ง `/api` ไป `http://localhost:3301` เองเมื่อไม่มี `API_URL`)
